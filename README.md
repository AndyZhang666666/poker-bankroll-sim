# Bankroll · 波动实验室

[在线体验](https://andyzhang666666.github.io/poker-bankroll-sim/) · [验收与设计记录](docs/VALIDATION.md) · [更新记录](CHANGELOG.md)

同样的获胜假设，为什么有些路径先停止，有些路径曾经达到目标、最终又回落？本项目用固定随机种子的合成模型，将这几个经常混淆的结果分开。无需登录、无 API Key、浏览器本地计算。

## 使用路径

1. 输入起始余额、每次基础额度、获胜概率假设、波动、场次与目标。
2. 看逐场分位带、10 条样本轨迹及最终余额分布，比较“额度不足而停止 / 曾经达标 / 最终达标”。
3. 换种子，观察有限随机抽样的变化；在风险分析中一次只改变一个变量。
4. 导出包含输入、种子、模型版本、统计结果和局限的 JSON 比较记录。

草稿仅保存在当前浏览器，损坏或禁用存储不影响计算。重算时仍保留上一组完整结果，但清楚标明其参数、种子，并禁用导出，避免新输入与旧结果混用。调整起始资金会保留目标倍数。

## 模型与事件定义

```text
f = 波动程度 / 10
单场变化 = ±基础额度 × (1 + U × f)，U 为 [0,1) 均匀随机数
下一场余额 = max(0, 当前余额 + 单场变化)
余额不足下一轮基础额度时停止；余下时点保留余额。
```

- 停止：起始或任一场后余额低于基础额度，不等于余额为零。结果字段 `bustRate` 为历史兼容名称，v2 含义是停止比例；界面及导出采用明确名称。
- 曾经达标：包含起始时点，任一模拟时点达到目标。到达目标后仍继续运行。
- 最终达标：最后一个时点仍不低于目标。不会高于曾经达标。
- 逐场 10%–90% 分位带是横截面分布，不是一条路径，也不是均值的置信区间。
- 95% Wilson 区间仅表示比例的有限抽样误差，不包含模型假设错误。公式参考 [NIST 统计手册](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

模型版本 `retained-balance-v2-2026-10-24` 修正了旧版“余额不够下一轮时，直接清零”的处理。固定案例与校验产物已按新定义重跑，数值变化不代表实际收益改善。

## 固定案例的可复现摘要

每组 10,000 条路径，种子 20260914。数据来自 [verify.json](results/verify.json)，不是用户实测。

| 示例 | 额度不足停止 | 曾经达标 | 最终达标 | 余额归零 |
|---|---:|---:|---:|---:|
| 保守型 | 2.64% | 88.29% | 75.60% | 0.59% |
| 平衡型 | 29.62% | 71.22% | 54.23% | 7.98% |
| 激进型 | 42.69% | 61.09% | 55.86% | 14.82% |

三个示例同时改变多个假设，不能据此做单因素因果判断；请用参数扫描固定其余变量。扫描只报告观察到的相邻门槛区间，不用插值伪装精确“安全额度”。

## 边界

各场独立同分布，获胜概率人为输入，无真实玩家行为、无抽水。单场变化可能超过一个基础额度，并只在零余额处截断，因此不是严格的一次买入损失上限模型。增加模拟条数只能减少抽样误差，不能让假设更真实。

布朗运动首次穿越零的公式保留在源码做数学对照，但与离散“额度不足而停止”不是同一事件。主界面不混画这两个事件，不将近似吻合写成模拟正确性的证明。

仅用于建模、数据解释与交互设计展示，不是财务预测、收益承诺或真钱下注建议。

## 开发

Next.js 15 / React 19 / TypeScript / CSS Modules / Chart.js，静态导出到 GitHub Pages。

```bash
npm ci
npm run dev
npm run check     # 28 个手算/确定性回归 + 固定案例生成 + 11 组边界测试
npm run build     # 导出 out/
```

Chrome 验收（先启动静态服务器；需要 Playwright）：

```bash
TEST_URL=http://localhost:8804/poker-bankroll-sim/ node scripts/test-browser.mjs
```

可通过 `PLAYWRIGHT_MODULE` 指定模块路径，`EVIDENCE_DIR` 指定截图与下载目录。风险扫描不保存逐场矩阵，逐点计算可取消；案例预先生成，不在页面打开时重复模拟。敏感性、案例和方法页面按需加载。
